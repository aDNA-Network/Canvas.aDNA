V-1 sync_hash

V-1 · What does sync.sync_hash hash? — three readings pass today, and four vaults are waiting

(b) — additive; every canvas that passes today keeps passing; Terminal and LP migrate one key; City already does it · ●●●●●

The Decision

canvas_std.compute_sync_hash hashes topology (sorted node ids + edge pairs, 16 hex). Terminal's 8 canvases store sha256(source markdown)[:16] (re-derived today: 8/8 source match · 0/8 topology match). City's twin stores the topology hash plus a non-standard sync.source_sha256. LatticeProtocol ADR-018 + LinkML Profile v0.1 define it as the master file's bytes, and gen-canvas (M-B1) is carded on your answer. Rule A-6 checks 16 hex chars only; the spec never says what is hashed. Which option? (a) sync_hash = source/master bytes · (b) sync_hash stays topology and the Standard registers sync.source_sha256 (64 hex) · (c) split into sync.topology_hash + sync.source_hash with sync_hash a deprecated alias through v2.x.
  • Migration priced per option. (a) breaks compute_sync_hash, Canvas's 26 adna_native canvases, City's topology usage, and every round-trip loader; requires a major bump. (b) breaks nothing that passes; Terminal moves its source hash from sync_hash to source_sha256 and regenerates (their generator already computes it); LP's gen-canvas writes both from day one; Home's one canvas is already non-conformant on other grounds. (c) is (b) with a rename nobody asked for and an alias to maintain.
  • Why topology stays in sync_hash. §8.1 already calls it 'the sync hash of the authoritative-source topology'; A-6 is in the round-trip layer because the hash↔source check is the round-trip's job. Noether's own argument for (a) — 'a schema master has no fromNode→toNode topology' — is an argument that the twin has one and the master needs a different key, i.e. for Q2.
  • What A-6 gains. With (b): source_sha256 must be 64 hex when present; when production: generated the validator may recompute topology and compare (ruled in P2b as advisory or hard — recommend advisory at extended, hard at adna_native).
  • Vernier P1's own observation stands: a source hash is the more useful question for a view canvas ('has my source moved?') and is third-party verifiable — (b) keeps it, named.
  • ⛔ Not a signature on the Standard. This verdict instructs LIP-0011 (P2b); the firewall touch is named in the Firewall section below and signed with the LIP.

Agent's Recommendation

RATIONALE

Choose (b). It is the only option with zero breakage for every current passer, it is what City already does, and it answers Noether Q1 '(b)' and Q2 'yes' in one stroke.

KEY FACTORS

  • Additive → minor bump (v2.5.0), not major
  • Terminal + LP migrate one key each; City migrates none
  • A-6 gains a semantic check it never had

RISKS

  • Terminal's 8 canvases read 'stale' to a conformant loader until they regenerate (they already do so daily)
  • (a) partisans — LP ADR-018 — must amend one line; memo #22 says so plainly
